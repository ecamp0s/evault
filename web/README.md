# eVault — the web client

The React SPA. **This is where the encryption happens**, which is what makes it
more than a frontend: under the zero-knowledge model of
[ADR-001](../docs/architecture/decisions/ADR-001-zero-knowledge.md) this
directory *is* the security boundary. The master password is derived here, the
vault key lives here in memory only, and everything that leaves for the API has
already been encrypted.

For what the product does and what it guarantees, see the
[root README](../README.md).

## Running it

Needs **Node 24 or newer**; there is an `.nvmrc`, so `nvm use` picks it. The 23.x
line does not satisfy the engine ranges several dependencies declare.

```bash
npm install && npm run dev
```

That serves on port 5173. **The hostname matters**: the Web Crypto API only
exists in secure contexts, so over plain `http://` the host has to be `localhost`
or end in `.localhost` — otherwise there is no registration, no login and no
encryption. `http://localhost:5173` works, and so does `app.evault.localhost`
behind a reverse proxy.

No `.env` is needed. The SPA asks for the API at `/api`, relative to whatever
origin serves it ([ADR-016](../docs/architecture/decisions/ADR-016-un-solo-origen-para-la-spa-y-la-api.md)),
so one build serves from any hostname. The only variable that still exists is
`DEV_API_PROXY`, for running Vite on its own against `php artisan serve` with
nothing in front — see [`.env.example`](.env.example).

## The commands

| | |
|---|---|
| `npm run dev` | Vite dev server, port 5173 |
| `npm run build` | production build into `dist/` |
| `npm run lint` | ESLint |
| `npm run test` | Vitest, watch mode |
| `npm run test:run` | Vitest, one pass |
| `npm run test:coverage` | with coverage and the `lib/vault` threshold, which is what CI runs |

## Where things are

| | |
|---|---|
| `src/lib/vault/` | the cryptography, the key in memory, export and import. `crypto.ts` is the only file that touches `crypto.subtle` |
| `src/lib/` | HTTP client, session, auth, clipboard and CSP |
| `src/pages/` | the screens |
| `src/components/` | shared components; `components/ui/` is generated by the shadcn CLI and is neither tested nor linted for fast refresh |
| `src/test/` | Vitest setup and the helpers for tests that need an unlocked vault |

Tests sit next to what they test, as `*.test.ts(x)`.

The coverage threshold applies per file over `src/lib/vault/`, and not over the
total, on purpose: an aggregate lets a brand new module sit at zero coverage
while the average stays green. That happened three times before the threshold
existed. The reasoning is in [`vite.config.ts`](vite.config.ts).
